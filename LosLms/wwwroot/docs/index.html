Overview

Your software pushes its loan accounts into a finance company's LOS/LMS, checks or removes them, and reads back the loans that company has disbursed in LMS. Everything is JSON over HTTPS. The company is always the one that approved your Connect request, so you never send a company id.

Authentication

Every call carries an access token in the Authorization header. You get the token by following the Connect guide: the customer clicks Connect in your software and approves a short code in LMS. There are no API keys to copy and paste.

Authorization: Bearer <access_token>
ScopeAllows
loans:writePush loans, delete loans.
loans:readCheck a loan, list loans, read disbursals.

Ask for loans:write loans:read when you connect. A token is valid for about an hour; use the refresh token to get a new one. A call without the right scope is answered 403; a missing or expired token is answered 401.

Base URL & format

https://los-lms.bhodhix.com/api/v1
  • Requests with a body use Content-Type: application/json. Replies are JSON.
  • Field names are camelCase.
  • Dates are text in yyyy-MM-dd form, for example 2026-09-30.
  • Money is a plain number in rupees with up to two decimals, for example 250000.00. No currency symbol, no commas.
  • Account numbers are compared without regard to leading or trailing spaces.

Push loans (create or update)

POST/api/v1/loansscope: loans:write

Sends a batch of loan accounts. Each loan is matched by accountNumber inside the connected company: new ones are created, changed ones are updated, identical ones are reported unchanged. Sending the same data again is safe. If any loan in the batch is invalid, nothing is saved and the reply lists every bad loan (422).

Request fields

FieldTypeRequired
loansarray of loan, 1 to 500 itemsyes

Each loan has the fields listed under Fields.

Example request

curl -X POST https://los-lms.bhodhix.com/api/v1/loans \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "loans": [
      {
        "accountNumber": "PV-000123",
        "customerName": "Asha Patil",
        "pan": "ABCDE1234F",
        "mobile": "9876543210",
        "product": "Two wheeler loan",
        "sanctionedAmount": 85000,
        "outstandingAmount": 61250.50,
        "status": "Live",
        "disbursedOn": "2025-11-03",
        "branch": "Pune"
      }
    ]
  }'

Example reply (200)

{
  "created": 1,
  "updated": 0,
  "unchanged": 0,
  "results": [
    { "row": 1, "accountNumber": "PV-000123", "result": "created", "id": 4172 }
  ]
}

row is the position of the loan in your loans array, starting at 1. result is created, updated or unchanged.

Example reply (422)

{
  "error": "validation_failed",
  "message": "2 loan(s) are invalid. Nothing was saved.",
  "details": [
    { "row": 2, "field": "customerName", "reason": "is required" },
    { "row": 2, "field": "pan", "reason": "must look like ABCDE1234F" },
    { "row": 3, "field": "accountNumber", "reason": "appears twice in this request" }
  ]
}

Possible errors: 400, 401, 403, 413, 422 (validation_failed, batch_too_large), 429. See Errors.

Check one loan

GET/api/v1/loans/{accountNumber}scope: loans:read

Tells you whether LMS holds this account, and its status.

curl https://los-lms.bhodhix.com/api/v1/loans/PV-000123 \
  -H "Authorization: Bearer $TOKEN"
{
  "exists": true,
  "loan": {
    "id": 4172,
    "accountNumber": "PV-000123",
    "customerName": "Asha Patil",
    "pan": "ABCDE1234F",
    "mobile": "9876543210",
    "product": "Two wheeler loan",
    "sanctionedAmount": 85000.00,
    "outstandingAmount": 61250.50,
    "status": "Live",
    "disbursedOn": "2025-11-03",
    "branch": "Pune"
  }
}

An account LMS does not hold is answered 404 with "error": "not_found". That is the normal "no" answer, not a fault. An account number may contain /; URL-encode the other special characters.

List loans

GET/api/v1/loans?page=1&pageSize=50scope: loans:read
QueryMeaning
pagePage number, from 1. Default 1.
pageSizeItems per page. Default 50, maximum 200.
{
  "page": 1,
  "pageSize": 50,
  "total": 132,
  "items": [ { "id": 4172, "accountNumber": "PV-000123", "customerName": "Asha Patil", "status": "Live", "...": "same fields as above" } ]
}

Items are ordered by id, oldest first. An empty page returns an empty items array.

Delete a loan

DELETE/api/v1/loans/{accountNumber}scope: loans:write
curl -X DELETE https://los-lms.bhodhix.com/api/v1/loans/PV-000123 \
  -H "Authorization: Bearer $TOKEN"
{ "deleted": true, "id": 4172, "accountNumber": "PV-000123" }

Unknown account: 404 not_found. Sending the loan again later creates it again as new.

Disbursals

GET/api/v1/disbursals?since=2026-09-01&page=1scope: loans:read

The loans this company has disbursed in LMS, so your software can open the account. Only applications whose funds were released are listed.

QueryMeaning
sinceOnly loans disbursed on or after this date (yyyy-MM-dd). Leave out for all.
page, pageSizeAs in List loans.
curl "https://los-lms.bhodhix.com/api/v1/disbursals?since=2026-09-01" \
  -H "Authorization: Bearer $TOKEN"
{
  "page": 1,
  "pageSize": 50,
  "total": 1,
  "items": [
    {
      "applicationId": "LN-2026-004912",
      "customerName": "Hemant Bhalerao",
      "loanAmount": 250000.00,
      "roi": 13.50,
      "tenure": 36,
      "disbursalDate": "2026-09-20",
      "firstEmiDate": "2026-10-22",
      "emiDayOfMonth": 12
    }
  ]
}

Items are ordered by disbursalDate, then applicationId. To stay in step, remember the latest disbursalDate you have processed and send it as since next time; a loan can appear again on that day, so match on applicationId. roi is the yearly rate in percent, tenure is in months. firstEmiDate and emiDayOfMonth are null when not set.

Fields

Loan (push and reply)

FieldTypeRequiredMeaning
accountNumbertext, 60 maxyesYour own loan account number. The key: the same number means the same loan. Must be unique within one request.
customerNametext, 200 maxyesBorrower's name.
pantextnoPAN, like ABCDE1234F. Lower case is accepted and stored in capitals.
mobiletextno6 to 14 digits, optional leading +.
producttext, 120 maxnoLoan product name.
sanctionedAmountnumber, 0 or morenoAmount sanctioned, in rupees.
outstandingAmountnumber, 0 or morenoPrincipal still to be repaid, in rupees.
statustext, 40 maxnoYour own status word. See Statuses.
disbursedOndatenoDay the loan was disbursed, yyyy-MM-dd.
branchtext, 100 maxnoBranch name.

A field you leave out, or send as empty text or null, is stored as empty. Every push replaces the whole loan: send all the fields every time, not only the ones that changed.

id in replies is LMS's own number for the row. You can store it, but accountNumber is the key you use in calls.

Statuses

The loan status is your word, not ours: LMS stores and shows it as you send it (for example Live, Closed, NPA). It does not change how the call behaves, and no other value is rejected. Disbursals are different: only loans that LMS has actually disbursed are listed, and there is no status filter.

Errors

Every error has the same JSON shape. details is always present and is empty unless the error has per-item detail (422).

{
  "error": "validation_failed",
  "message": "Plain-language explanation.",
  "details": [ { "row": 2, "field": "pan", "reason": "must look like ABCDE1234F" } ]
}
StatuserrorMeaningWhat to do
400bad_requestThe body is not valid JSON, or a field has the wrong type (for example text where a number belongs).Fix the request. Nothing was saved.
401unauthorizedNo token, an expired token, or a connection that was cut in LMS.Refresh the token and retry once. If that is refused, ask the user to Connect again.
403insufficient_scopeThe connection was approved without the scope this call needs.Ask the user to Connect again and allow both scopes.
404not_foundNo loan with that account number in this company.Treat as "not in LMS".
405method_not_allowedWrong HTTP method for that address.Check the method.
413too_largeThe request body is over 2 MB.Send fewer loans per call.
422validation_failedOne or more loans (or a query value) are invalid. details lists each row, field and reason.Fix those loans and send the whole batch again. Nothing was saved.
422batch_too_largeMore than 500 loans in one call.Split into batches of 500 or fewer.
429rate_limitedToo many requests from one address.Wait a minute, then retry.
5xxerrorLMS had a problem or is temporarily down.Keep your data, retry in a few minutes. Pushing again is safe.

Limits & billing

LimitValue
Loans per push500
Request body2 MB
Page size200 (default 50)
Request rate120 requests per minute from one address
Access token lifeAbout 1 hour

Idempotency: pushing a loan again with identical data changes nothing and is reported unchanged. It is safe to resend a whole book after a timeout or a crash, and to send the full list every day.

Billing: these loan endpoints are not metered per call. Per-use charges for LMS's own verification services (identity, bank checks, e-sign) are billed to the finance company and are not part of this API.

Audit: every change you make is logged by LMS together with your software's name, as shown on the Allow screen.
